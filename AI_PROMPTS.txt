Build email verification (ACC-02): a verification link at registration, GET /api/auth/verify-email, a resend option, and booking blocked until the email is verified, behind an environment switch that is off by default so graders can still book locally.

How the output was used:
Built test-first on the token store and MailService from ACC-07. Registration now creates the user as unverified (older, seeded and admin-made accounts count as verified) and emails a 24-hour single-use link in the background, so a mail failure never fails registration. verify-email and resend-verification are rate limited. A VerifiedEmailGuard acts on routes marked @RequireVerifiedEmail() (flight booking hold, hotel reservation) only when EMAIL_VERIFICATION_REQUIRED is exactly "true", and answers 401 instead of passing if it ever runs without a logged-in user. A unit test pins the marks on the real booking routes. My first version registered the guard in the global AuthModule, which broke the no-database foundations e2e suite; I moved it to AuthApiModule. Added e2e tests (16 for the flow and the switch), README rows and the new variable name in .env.example. Reviewed the diff.
